## 1. 学校侧的关键事实(决定会话与登录设计)

1. **验证码与失败额度在 EC 网关层**:同一 IP 上 2 次登录失败,之后该 IP 上的
   登录会返回 `RndImg=1`(需要验证码),与账号无关。已建立的会话不受影响。
2. `RndImg=1` 在 `GET /por/login_auth.csp` 阶段就能读到,**此时还没有提交
   密码,不会消耗失败次数**。这是预检(pre-flight)的基础。
3. **EC 登录与 UAAP 登录可以解耦(2026-10-14 实测)**:把一个已完成 EC 登录的
   会话的网关 cookie(TWFID 等)克隆到新会话,可以完成 UAAP 登录,且可以
   派生给不同账号——两个账号的教务数据(实测 GPA 3.98 / 4.05)互不串号。
4. **TWFID 绑死出生出口 IP(2026-10-17 实测,ProxyPool 转向的核心依据)**:
   在代理 IP 上出生的完整会话(EC+UAAP 通过),克隆全部 cookie 到直连会话
   后业务调用 500;同一代理会话原地业务调用 200。**TWFID 绑死出生出口 IP,
   粘性是强制的**。此前的"学校会话不绑出口 IP"(§5 实测)只适用于 UAAP 层,
   不适用于经网关代理的业务会话。后果:多出口世界共享槽模型不成立,转向
   ProxyPool 1:1(§7)。
5. **CF Worker 出口不可用(E1 已实测)**:100 次调用全部从同一个共享 IPv6
   (`2a06:98c0::/32`)出去,97% 落在西雅图机房,placement 提示无效。该地址
   与 Cloudflare 全部客户的 Worker 共享,失败额度不可控,且每请求约多
   350ms。故放弃。
6. 验证码污染约 **3 分钟**自动恢复(E2 中间数据,两次观测一致)。
7. 网关区分"密码格式错误"与"密码错误"(代理调试期间见过 `20026 bad password
   format`),这支撑 §5.1 的本地预校验设计。
8. **网关 Location 改写与会话有效性绑定(2026-10-15 实测)**:会话有效时,
   网关把 CAS 的 service 重定向改写回 vpn2 命名空间;会话失效后仍代理但
   不再改写——Location 泄出原始内网域。已修:walk 检测逃逸 → 单飞恢复一次
   并重试。
9. **槽/会话活性只有"改写自测"能证明(2026-10-16 实测)**:网关对老化 TWFID
   照样代理、身份登录照样"成功"、心跳一切正常,只有 service 重定向的改写
   会停。池内(无 CASTGC)原理上不可观测。已修:借槽后身份登录成功即自测,
   死槽退役。(§7.5 会话组的恢复仍沿用该自测。)
10. **sdp-app-session 只认域级 TWFID(2026-10-16 实测)**:网关每卡发两颗
    TWFID cookie(host-only + `.vpn2.aufe.edu.cn` 域级);`sdp-app-session`
    头只认域级值。已修:`TWFID()` 回退优先域级 cookie。
11. **TWFID 中途轮换,jar 是实时真相(2026-10-17 实测)**:网关在身份/铸票
    中途轮换 TWFID,内存 pin 反噬 → `TWFID()` 优先级反转:jar 的域级
    cookie 是实时真相优先,内存 pin 只作兜底。
12. 未知、需要实验(见 §12):UAAP 层失败是否计入网关 IP 失败额度、
    20026 格式错误映射、captcha 率与重灌失败率进 admin health。
13. **aac/labor 服务票长期固定**(用户 2026-10-17 反馈,并已在服务端利用):
    拿到 TWFID + 票即可直接请求业务数据;票实质永久,用户去年上报漏洞后
    学校才手动刷新过一次。因此票跨会话持久化(随快照封存),铸票链 4 跳
    只在"该用户从未铸过票"时发生一次。
14. **出口端口 RTT 方差大**(2026-10-17 全量实测,100 端口到网关登页):
    快档 ~1.19-1.45s(约 45 个)、中档 ~2.1-2.3s(约 30 个)、慢档
    2.7-8.0s(约 25 个)。同一请求慢口比快口贵 2-6×,是 p90 长尾的主源
    (登录 p90 23.5s、课表 p90 12.5s)。

## 2. 总体架构

模块化单体:一个二进制 `loveaced` + 一个 Postgres。

```
server/
  cmd/loveaced/            入口
  (真库用户压测工具未随开源仓库发布,§7.8)
  internal/
    api/{v1,public,admin}/ Huma 路由与处理器(薄,只做编排)
    dto/ mapper/           对外数据结构;school 模型 → dto 的唯一转换处
    auth/                  我们自己的令牌、设备、刷新令牌
    vault/                 学校凭据信封加密、授权同意记录、审计
    schoolsession/         UAAP 会话、快照、验证码挑战与三循环、账号会话组
    gate/                  登录准入:预校验、限流、排队、凭据一次失败即停
    cache/                 读穿缓存、单飞、过期数据兜底
    health/                被动健康判定(分层、依赖感知)
    stats/                 使用统计
    calendar/ announce/    校历、公告
    jobs/                  River 任务注册
    store/                 sqlc 生成代码 + 事务封装
  db/{migrations,queries}/
```

## 3. 对外 API 约定

- 资源名词复数,版本前缀 `/v1`;管理接口 `/admin/v1`;公开接口 `/v1/public`(无需认证)。
- 成功响应统一为 `{"data": ..., "meta": {...}}`。来自学校的资源,`meta` 带 `fetched_at`(ISO-8601,+08:00)、`stale`(布尔)、`source`(`live|cache`)。
- 列表:游标分页 `?limit=&cursor=` → `{"data": [...], "meta": {"next_cursor": ...}}`。
- 错误:`application/problem+json`(RFC 9457),固定 `code` 字段,见 §3.1。
- 时间一律 ISO-8601 +08:00;金额用整数分(`amount_cents`);学期结构化 `{academic_year, semester}`。
- 字段 snake_case;枚举用稳定的小写英文串,不透传学校的中文状态。
- 写操作必须带 `Idempotency-Key`;结果不确定(例如缴费)返回 `202` + `/v1/operations/{id}`,后台对账。
- 条件请求:GET 支持 ETag/If-None-Match;限流响应带 `Retry-After` 与 `RateLimit-*`。
- 安全头、CORS 白名单、请求体大小上限、请求超时;所有 handler 使用请求的 `ctx`。

### 3.1 错误码(节选)

| code | HTTP | 含义 |
|---|---|---|
| `auth.invalid_token` / `auth.token_expired` | 401 | 我们的令牌无效或过期 |
| `school.credentials_invalid` | 401 | 学校密码错误(凭据状态转为 invalid,停止一切自动登录) |
| `school.captcha_required` | 409 | 需要验证码,带 `challenge_id` |
| `school.captcha_incorrect` | 422 | 验证码错误,可重试 |
| `school.unavailable` | 503 | 学校不可用(带 `layer: gateway|service`) |
| `school.busy` | 503 | 我们对学校的准入已满,带 `Retry-After` |
| `school.parse_changed` | 502 | 学校页面结构变了,解析失败 |
| `school.outcome_unknown` | 202/409 | 写操作结果不确定,走对账 |
| `auth.password_invalid_format` | 422 | 密码含学校不支持的字符(如全角),本地拦截,未触碰学校,带 `violations` |
| `auth.cooldown` | 429 | 密码错误过多进入冷静期,带 `retry_after_seconds` / `cooldown_until` |
| `auth.session_limit` | 409 | 该账号活跃 UAAP 会话已达上限(默认 5),带 `active_sessions` 引导吊销 |
| `rate_limited` | 429 | 我们自己的限流 |

## 5. 认证与设备

- 用户用学校账号密码登录,由我们去学校验证;通过后发放**短期访问令牌**(Ed25519 签名 JWT,15 分钟)和**可轮换刷新令牌**(随机串,库里只存哈希,检测复用,复用则整条链作废)。
- 令牌按设备管理;用户可以查看并踢设备。
- admin 与用户体系完全分离,强制 TOTP,所有操作写审计。
- 我们的登录接口本身就是学校账号的"密码试探器",必须限流:按 IP、按账号、按设备,失败多次后要求 Turnstile。

### 5.1 密码输入预校验(学校不支持全角符号)

现象:学校不支持全角符号,有些用户(多半是输入法处于中文/全角状态)一直输、一直错。每一次错误提交都可能消耗网关的失败额度(§1;UAAP 层失败是否计入网关额度待 E8 实测),还会让账号靠近学校侧的锁定线。**这类请求根本不该送到学校。**

- 在 `gate/` 里做**本地预校验**,发生在任何网络请求之前:不通过则直接返回 `422 auth.password_invalid_format`,**不触碰学校、不计入失败次数、不进入冷静期**。
- 校验项(暂定规则,待 §12 的 E5 实测确认学校实际接受的字符集后收紧或放宽):
  - 含全角字符(全角标点和符号、全角字母数字,Unicode 的 Halfwidth and Fullwidth Forms 区块)。
  - 含非 ASCII 字符(中文、中文标点,如 `,` `。` `!` `「」`)。
  - 首尾有空白(粘贴时常带入),含换行、制表符、零宽字符、BOM、其他控制字符。
  - 长度为 0 或超出学校上限。
- 错误响应只告诉用户**哪里有问题**,不回显密码内容:
  ```json
  {"type": "...", "status": 422, "code": "auth.password_invalid_format",
   "detail": "密码包含学校不支持的字符",
   "violations": [{"index": 5, "category": "fullwidth_symbol"},
                  {"index": 9, "category": "whitespace_edge"}],
   "hint": "请切换到英文半角输入后重新输入"}
  ```
  `category` 取值:`fullwidth_symbol | fullwidth_alnum | non_ascii | whitespace_edge | control | zero_width | too_long | empty`。
- **不在服务端静默转换**(不自动把全角改成半角再提交):转换可能把用户真正的密码改错,而且会掩盖问题。如果要提供"一键转半角重试"的体验,由客户端本地完成转换后让用户确认再提交。
- 规则同时通过 `GET /v1/public/app-config` 的 `password_rules` 字段下发(字符集、长度上限、首尾空白规则),客户端在输入框上就能实时提示,连请求都不用发。
- 同样的预校验也用在"更新已保存凭据"(`PUT /v1/me/credentials`)和自动化授权入口。
- 日志与存储:密码和它的任何部分都不进日志。只记录布尔标记和类别计数(例如"本次因全角被拦截"),用于指标,见 §5.2。
- 待确认:
  1. 学校网关对格式不合规的密码是返回专门的"格式错误"类结果码,还是和"密码错误"一样?(之前调试代理时见过网关返回 `20026 bad password format`,说明网关区分格式错误。)
  2. 格式错误**是否**计入"同 IP 3 次失败触发验证码"?
  3. EC 网关和 UAAP/CAS 两层各自接受的字符集是否一致?

### 5.2 密码错误监测与冷静期

目标:定量限制"对学校的错误密码提交次数",既保护学校账号不被锁、保护网关额度不被污染,也让用户在不得其法时得到明确指引,而不是无限重试。

**什么算一次"计数的失败"**:只有"真正提交给学校、并被学校判定为密码错误"才计数。下列情况都**不计数**:预校验被拒(§5.1)、被冷静期拦截、命中"已拒绝指纹"的本地拒绝、网络或学校故障、验证码错误。

**每个请求按以下顺序过关**(越靠前越便宜,越能避免打到学校):

1. 格式预校验(§5.1)
2. 已拒绝指纹:同一(账号, 密码)的 `HMAC(pepper, account‖password)` 在 15 分钟内已被学校拒绝过,则本地直接返回 `401 school.credentials_invalid`,带 `meta.cached=true`,**不再提交**。TTL 取 15 分钟(而不是更久),是为了防止用户在学校官网把密码重置成刚才那个值后被我们拦住。
3. 账号冷静期(见下表)
4. 设备 / 客户端 IP 限额(见下)
5. 网关预检(§7.5),然后才提交

**账号冷静期阶梯**(按账号,滚动 6 小时窗口内的计数失败次数;数值是起始建议,**要用 E2/E6 的实测数据校准**):

| 窗口内第几次失败 | 之后的冷静时间 |
|---|---|
| 1 | 无(打错一次很正常) |
| 2 | 10 秒 |
| 3 | 1 分钟 |
| 4 | 5 分钟 |
| 5 | 30 分钟 |
| 6 | 2 小时 |
| 7 及以上 | 6 小时(上限 24 小时) |

- 硬上限:同一账号 30 分钟内最多向学校提交 5 次,不管冷静阶梯处在哪一档。
- 成功登录立即清零该账号的计数。管理员可手动清零。
- 冷静期内的请求返回:
  ```json
  {"status": 429, "code": "auth.cooldown",
   "detail": "密码错误次数过多,请稍后再试",
   "retry_after_seconds": 300, "cooldown_until": "2026-10-12T18:30:00+08:00",
   "failures_in_window": 4,
   "hint": "确认输入法为半角;如已修改过密码,请先在学校官网确认新密码"}
  ```
  同时带标准 `Retry-After` 头,客户端据此显示倒计时。冷静期**只拦我们对学校的提交**,不阻止用户读公告等不需要学校的接口。
- 第 3 次失败起,响应里附上更明确的指引(检查输入法与全角、检查是否改过密码、官方找回入口)。

**设备与 IP 维度**(针对撞库与暴力尝试;作用于我们自己的登录接口):

- 单个客户端 IP:1 小时内 10 次计数失败 → 要求 Turnstile;30 次 → 封禁 1 小时。
- 单个客户端 IP 在 1 小时内对 **5 个以上不同账号**都失败 → 判定为撞库,直接封禁并写审计。
- 单设备:同账号阶梯之外,单设备 1 小时内 10 次失败触发 Turnstile。
- 与网关额度的关系:每次计数失败都可能消耗网关的验证码额度(UAAP 层失败是否计入待 E8 实测),所以账号冷静期、已拒绝指纹、格式预校验这三道门,本质上就是在**保护额度**。网关侧仍保留自己的预检与冷却(§7.5),两层互相独立。

**已保存凭据的静默重登**:

- 失败 **一次即停**:标凭据 `invalid`,不重试,**不走冷静阶梯**(那是给交互式登录用的)。
- 用户下次打开应用时,`GET /v1/me` 带 `credential_state: "invalid"`,客户端提示重新输入密码;重新输入走同一套 §5.1/§5.2 的门。

**监测与告警**:

- 指标(按小时聚合):各分类的数量——`format_rejected`、`cached_reject`、`cooldown_blocked`、`wrong_password`、`captcha_required`、`login_success`;以及按"账号数"而不是按次数统计的"卡住的用户数"(窗口内失败 ≥ 3 次且没有成功)。
- 存储的个人尺度数据只有:`HMAC(account)`、时间、分类、布尔标记(本次是否含全角/首尾空白/控制字符、长度档位)。**不存密码、不存密码片段**,保留 7 天。
- 管理端看板:卡住用户的数量与趋势(只显示脱敏 ID)、各分类占比、被封禁的 IP/设备列表。
- 告警:
  - `format_rejected` 占比突增 → 客户端输入框体验有问题(比如某个版本没做半角提示)。
  - `wrong_password` 全局占比突增 → 可能是学校集中要求改密,自动生成一条状态公告提示用户,同时降低冷静期的敏感度(管理员可开关)。
  - 单个 IP 对多账号失败 → 撞库告警。
- 这些数据同时是校准冷静阶梯的依据:看第几次失败之后用户通常就放弃或成功。

## 6. 学校凭据保险库

- 信封加密:每用户一个 DEK(AES-256-GCM),由 KEK 包裹;AAD 绑定 `user_id`;记录密钥版本,支持轮换(重新包裹 DEK,不碰密文)。
- 另存 `HMAC(pepper, 密码)` 指纹,用于判断"这个密码学校已经拒绝过",避免重复撞学校。
- KEK 通过 `KeyProvider` 接口取得:起步是环境变量/文件(权限 0400),以后可换云 KMS。
- **网关密码**:默认等于学校密码;用户登录时可单独提供、单独保存(字段允许为空 = 同学校密码)。EC 入池登录(§7)使用它。
- 凭据状态机:`unverified → valid ↔ invalid`。进入 `invalid` 后**所有自动登录立即停止**,直到用户用新密码重新登录。
- 自动化授权单独记录:同意文案版本、时间、可撤销。撤销或注销账号时销毁 DEK(硬删除)。
- 管理员**不能**解密用户凭据;只有受限的后台任务能在受限上下文里使用,且每次解密都写审计。
- 风险记录:KEK 丢失等于全部凭据报废,需要备份方案;数据库开启 PITR。

## 7. 直连会话模型与验证码三循环(2026-10-21 重写,M4)

> 史实链:2026-10-14 EC 会话池共享槽 → 2026-10-17 ProxyPool 1:1 →
> **2026-10-21 直连化(M4,一刀切,不留双路径)**。退场依据(E-D 实测,
> §1 第 15 条):直连 100 并发 burst 全量登录 99/100 ok、p50 4.3s,比
> 池下(E-B p50 8.9s)快一倍;错 UAAP 密码死在 CAS 层、不烧 EC 额度,
> 借位验证失去存在意义(其宿主预算烧穿类缺陷一并消失)。

### 7.1 模型

**一个 EC 会话对一个 UAAP 身份;全部会话骑服务器直连出口。**

- 出口即身份不再由我们管理:全体会话共享服务器 IP,网关的 per-IP 失败
  额度(同 IP 2 次失败 → 验证码模式)由**验证码三循环**承受(§7.5)。
- 恢复 = **原地重登**(直连出口不变,新 TWFID 替换旧 TWFID;E-A 的
  "TWFID 绑死出生 IP"在单一出口世界自动满足)。

### 7.2 登录流程

1. 本地门(§5.1/§5.2):格式预校验 → 已拒绝指纹 → 账号冷静期。
2. **全量登录(唯一路径)**:过全局闸 → 直连 EC 登录(撞验证码走三循环)
   → UAAP 登录 → 注册入组。
   - **错 UAAP 密码**:EC 成功后死在 CAS 层(文案「密码输入错误，您还有
     "N"次输入机会。」,账号级约 5 次计数),**不烧 EC 失败额度**;
     hook 标 vault 凭据 invalid + audit,静默重登短路。
   - **错网关密码**:EC 20004,真判,hook 同上——这是唯一烧 EC 额度的
     失败路径,由三循环+冷静期承受。
   - **要求改密是致命的**(凭据正确):fatal 403,hook 不触发。
3. 端口失败账本随代理池删除(无端口可记;失败记账收敛为 CaptchaStats
   与账号冷静期)。

### 7.3 会话生命周期

- **业务调用**全部直连(transport 无代理)。
- **惰性策略**:不做定时心跳;过期由恢复逻辑重登一次并重放(读请求)。
- **过期风暴**:读请求排队,恢复排队,缓存兜底;**绝不并发硬冲网关**。
- **冷启动**:无快照时,首登即真实登录当播种机;不再有独立重灌循环。
- **重启**:in-memory 会话清空,冷快照恢复带回凭据,原地重登。

### 7.4 会话组

- 每用户一条 UAAP 会话,多设备共享;注册收敛:所有设备条目重指向
  最新会话;登出引用计数,最后一个绑定才拆。
- 组上限(默认 5)只约束完整登录;第 6 个完整登录拒绝:
  `409 auth.session_limit`,带活跃列表。

### 7.5 验证码三循环(验证码原生化,M1-M3)

- **L1 单挑战一次提交**:挑战绑定 TWFID,**一次性**(2026-10-20 实测:
  同一 TWFID 第 2 次提交 24/24 作废);判错必须重新取图重猜重提,
  取 auth 页/图都是零额度 GET。
- **L2 登录内自动环**:solver(common.onnx,oracle 实测接受率 34.8%)
  在场且熔断闭合时,ecPhase 撞验证码自动"取图→解→提交";20023 =
  码错,立刻换新挑战;20004 = 码已通过、凭据被拒(照实 fatal 并记
  金标);上限 8 次取图/5 轮提交,耗尽回退人工。
- **L3 熔断 + 人工回退**:滑动窗 20 内接受率 <15% 或连续判错 → 开闸
  10 分钟,新登录直接走人工挑战(`ChallengeImage`/`SolveChallenge`)。
  **E-D 洪水实测(30 错网关密码)**:洪水期网关对同 IP 的验证码提交
  一律拒绝(139/139,挑战存储被并发逐出),硬解无意义——熔断停手、
  等 ~3 分钟自愈是唯一正确姿势;洪水停止后 29/29 一次过闸。
- **判卷沉淀(M3)**:所有有结论的提交(金标/困难负样本)落 zstd 日切
  (`captchastore`),供后训练;挑战与人工手解同样沉淀。
- 批量囤积挑战会被网关整批失效(2026-10-20 run3)——环内每挑战
  <1s 生命周期,永不囤积。

### 7.6 性能层(2026-10-17 晚轮,保留项)

1. **票持久化**:`session.Tickets()`/`SeedTickets()` 原语;快照恢复与
   全量登录都先种入已存的 aac/labor 票,铸票链"每会话一次"降为
   "每用户一次(跨重启存活)"。`reset_ticket` 语义不变。
2. **读缓存 stale-while-revalidate**(§11.3):过期条目立即返回 +
   后台单飞刷新,冷会话后首批数据直接命中缓存上屏。

(端口延迟探测/带宽租借/验证记忆随代理池与借位验证退场;直连基线
p50 4.3s 已优于池下 8.9s。)2026-10-26:登录里的 JWC 回调改为后台单飞
(`core/session/service_callback.go`):UAAP 成功即返回;JWC 请求经
`AwaitServiceCallback` 门控,恢复重放前等待同一门;登出 join 未完成的回调,
且被取代/登出的回调不产生可用性观测。

### 7.8 已知缺陷与风险

- **CAS 账号级错密码计数**:约 5 次错密码锁账号(「您还有N次」)。
  应用层账号冷静期(§5.2)先于学校锁定;学校侧锁定后的解锁流程未知
  (§12)。
- 20026(请求形态被拒/CSRF 不匹配)2026-10-26 起单独映射为 `request_rejected`:
  不判卷、不进验证码沉淀,落 temporarily_unavailable 并计入 gateway 失败样本。
  唯一观测到的 `20026 bad password format` 实为我方 URL 转义 bug 所致,
  不代表网关有密码格式校验(格式校验仍在本地 §5.1)。
- **20041 节流(2026-10-26 偏离 Rust parity)**:`maybe attacked` 是网关的
  攻击嫌疑节流,不判卷、不判密码。此前按验证码处理,会把节流当错码记入困难
  负样本并继续提交;现为 `ECMaybeAttacked`:循环立即停止、不记判决、返回可重试
  429(`rate_limited`),不再弹人工验证码。
- **服务器 IP 成为唯一出口(终态,2026-10-23 代理订阅已注销)**:验证码
  污染影响全体登录,由三循环承受,污染窗口 ~3min 自愈;出口多样化若将来
  重启,需要新的供应商选型与租借模型评估,不存在一键回退。

- 同一账号并发登录做单飞(§7.2)。
- 学校 VPN 可能有并发用户数上限,会话要尽快驱逐(未验证,见 §12)。
- **上线前置(已完成,2026-10-14)**:core 的两个缺陷(goroutine 泄漏、
  `CancelOperation` 未真正取消)已修复;bench 1000 会话 goroutines 1→1,

## 9. 健康监测(被动为主)

- 分层:**L0 = VPN 网关**,**L1 = 各业务服务**(jwc/ykt/aac/labor/isim/competition/repair)。
- 数据来源:真实请求的结果。一个逻辑操作只计一次;零样本记 `unknown`;返回 200 的登录页不算成功;**密码错不算学校故障**。
- 依赖感知:L0 异常时,L1 标 `blocked_by_gateway`(显示为"未知/受网关影响"),不报各服务宕机,也抑制重复告警。
- 判定要求最小样本量**和最小独立账号数**(防单用户噪声);带滞回,避免抖动。
- 没有流量(深夜)时,状态衰减为 `unknown` 并显示最后已知状态与其年龄,**不判宕机**。
- **零凭据 L0 探测(已确认开启,受活跃度驱动)**:`GET login_auth.csp`,不带账号、不提交任何东西、不消耗失败次数。它给出:网关是否可达、我们的出口 IP 是否被验证码污染,以及污染的恢复时间。
  - **探测只在有人在用时进行**:系统记录"最近一次真实用户请求时间"。有请求后进入 `active`(探测间隔 60 秒);连续 N 分钟(默认 10 分钟,可配)无任何用户请求则进入 `idle`,**完全停止探测**,直到下一次用户请求唤醒。
  - 被污染期间才需要更频繁地探测恢复(但同样受 `idle` 限制:没人用就不探)。
  - 全局并发上限 1~2 个探测在途,探测间隔加抖动,总量有硬上限(每分钟 1 次)。
  - 不长期占用学校服务器是硬原则:探测不需要登录,不占 VPN 并发用户名额。

### 9.1 用户冷却(Session Cooling)

目的:不长期占用学校服务器的会话资源。

| 状态 | 条件 | 行为 |
|---|---|---|
| `hot` | 最近 5 分钟内有请求 | 会话常驻内存,读请求直接复用 |
| `warm` | 5~30 分钟无请求 | 会话仍保留,**不做任何心跳**;下次请求惰性检测、必要时重登 |
| `cold` | 超过 30 分钟(可配)无请求 | 主动登出 UAAP 会话(释放 VPN 名额),内存驱逐,cookie 快照加密落库后删除明文(§7.4) |
| `dormant` | 超过 7 天无请求 | 删除会话快照;凭据保留(用户已授权),不再做任何后台动作 |

- 用户冷却后再来:`cold` 用户的第一次请求触发一次静默重登(走主道,见 §7.3),对用户表现为首请求稍慢。
- 自动化任务(用户已授权)也要遵守:后台任务登录 → 取数据 → **立即登出**,不保持会话,并带抖动分散在时间轴上。
- 冷却状态与探测活跃度联动:`idle` 状态下不探测,也不对 `cold` 用户做任何预热。
- 指标:各状态人数、冷启动重登次数/成功率,用来评估冷却阈值是否合适。
- 额外监控**解析器漂移**:每个解析器的 `parse_error` 率。学校改页面是最常见的故障。
- 管理员可手动标记"维护中"。数据存 1 分钟桶,对外 `GET /v1/public/status`。

## 11. 校历 / 公告 / 缓存 / 统计

### 11.1 校历(替代原"学期周")

- `day_rules`:`holiday`(放假)、`makeup`(调休,字段 `{date, follow_week, follow_weekday}`,表示"这天上第几周的星期几的课")、`exam`、`vacation`。

- admin:规则增删改 → 草稿 → 预览 → 发布(版本号递增、ETag、审计)。
- `GET /v1/me/academic/timetable?from&to`:课表 × 校历,已处理放假与调休。

### 11.2 公告

- 字段:级别、markdown 正文、受众(`pre_login | post_login | both`)、平台与版本范围、起止时间、置顶、是否必须确认、状态。
- 登录前:`/v1/public/announcements`(标准 HTTP 缓存头 max-age=60 +
  stale-while-revalidate;2026-10-15 明确**服务直连用户、前面无 CF**,缓存
  头按通用 HTTP 设计,不绑定任何 CDN);登录后:`/v1/me/announcements`
  (带已读/确认状态,`Authorization` 在,一律不缓存)。
- 学校故障时可自动生成状态公告。

### 11.3 缓存

- 读穿缓存,按资源设 TTL(余额 30 秒,成绩分钟级,课表/培养方案小时级),按(用户, 资源)单飞。
- 学校不可用时返回旧数据并带 `stale=true`,不报错。个人数据在库里加密存放。
- **stale-while-revalidate(2026-10-17)**:过期条目立即返回(元数据
  `source=cache`,后台单飞刷新、与前台共享同一把 flight key);冷会话后
  首批数据因此秒开。刷新失败不报错、不丢旧值(退化为 stale-if-error)。
  仅用于读路径;写操作前置条件不得走 SWR。

### 11.4 统计

- 事件异步批量写入;用户标识用 HMAC 脱敏,不存内容。
- River 周期任务每分钟汇总;原始事件留 30 天,汇总留 1 年。
- 指标:DAU/MAU、功能调用量、各服务成功率与延迟、登录漏斗、验证码触发率、平台/版本分布。

## 15. 自动评教(后台任务池,2026-10-26)

**当前状态**:引擎、存储、接口已实现,逻辑通过假学校与假时钟测试(含 50 用户并发与排队)。教评开放前**未对真实学校发出任何评教请求**。默认关闭:`LOVEACED_TEACHER_EVAL_ENABLED=1` 才启用。教评不做同意控制:条款同意由小程序登录流程负责,后端不记录也不检查。

### 15.1 节奏(三端一致)

| 项 | 值 | 备注 |
|---|---|---|
| 课程错峰 | 6 s | 同一任务内;不同用户之间不协调 |
| 提交前等待 | 140 s | prepare 之后 |
| 首次访问保护 | `infoTime+5s`,最多 2 次 | 超过 → `protection_unresolved` |
| prepare 失败 | 立即重试 1 次 | |
| 提交结果不明 | 先核实(verify),确认未评才重提 | 每门课最多 2 次提交 |
| 批后补偿 | 1 轮 | 仅 `prepare_failed` 与已核实未评的 `submit_failed` |

与客户端的刻意差异(更严格):核实本身出错 → 不重提(客户端会重提);第二次提交失败后仍核实一次。

### 15.2 架构

- `server/internal/teachereval`:`Pool`(容量 50 按用户,排队上限 200)、`runner`(每任务一个,每门课一个 goroutine)、`Clock`(生产用真时钟,测试用假时钟)、`RemoteFactory`。
- 每一步都经 `SessionFor` 取会话:刷新活跃时间,防止 `SweepCold` 在任务中途清扫会话。
- 写请求不重放:会话过期时 `Send` 返回 `outcome_unknown`,引擎只能核实,不能盲提。
- 一人一个活动任务:由 `teacher_eval_tasks` 的部分唯一索引保证。
- 评分模式 `random`(默认:80% 满权重、否则次高权重组)或 `max`(全部满权重),由任务创建时选择;课程范围固定为"全部未评课程"。

### 15.3 状态与错误

- 任务:`queued → running → completed | failed | cancelled | interrupted`。
- 课程:`pending → preparing → waiting → submitting → verifying → success | failed | cancelled`。
- 失败类型 `error_kind`:`captcha_required`、`session_required`、`closed`、`protection_unresolved`、`paused`、`interrupted`、`prepare_failed`、`submit_failed`、`verify_unknown`、`unknown`。

### 15.4 接口

| 方法 路径 | 用途 |
|---|---|
| `GET /v1/me/teacher-eval/status` | 学校是否开放教评;`open=false` 时前端显示"教评未开放";`fresh=true` 绕过 60 秒缓存 |
| `POST /v1/me/teacher-eval/tasks` | 创建任务,必须带 `Idempotency-Key`;body `{"score_mode":"random"|"max"}`;202 |
| `GET /v1/me/teacher-eval/tasks/active` | 当前活动任务,无则 404 |
| `GET /v1/me/teacher-eval/tasks[?limit=]` | 历史任务 |
| `GET /v1/me/teacher-eval/tasks/{id}` | 任务、各课程进度、最近 50 条脱敏日志 |
| `POST /v1/me/teacher-eval/tasks/{id}/cancel` | 取消;已提交的评价无法撤回 |
| `GET /v1/admin/teacher-eval/pool` | 运维视图(需管理员令牌) |
| `POST /v1/admin/teacher-eval/pause` | 全局暂停开关 `{"paused":bool}` |

创建的错误码:`teacher_eval.disabled` 503、`teacher_eval.paused` 503、`teacher_eval.closed` 409(学校关闭时创建即拒绝,不落库)、`teacher_eval.task_active` 409(返回 `task_id`)、`teacher_eval.queue_full` 429、`invalid_argument` 422(评分模式非法)。

### 15.5 持久化

迁移 0006:任务、课程、日志(每任务上限 200 行)。迁移 0007 删除 0006 建的同意表(同意不入库)。**不存表单内容与评语**,只存课程键、结果码与时间。

### 15.6 重启与暂停

- 重启:`running` → `interrupted`,其中在途课程 → `cancelled`;`queued` 重新入队。不自动续跑:在途提交可能已到达学校,只能由用户重新发起。
- 暂停:拒绝新建;运行中任务在下一步停止(`failed/paused`),不再发起提交。

### 15.7 关闭态

- 创建时读学校首页:关闭 → 409 `teacher_eval.closed`,不落库。
- 运行时首次访问保护闸再读一次:关闭 → 任务失败 `closed`。
- `status` 对学校不可达的处理:返回 30 分钟内最近一次结果并标 `stale=true`;更早则 503。

### 15.8 未验证项

4. 合规:`docs/handover` 风险表第 10 条已把自动评教(80% 最高权重 + 随机评语)列为灰区;条款文本与产品决策待定。
5. `max` 评分模式会让所有单选题取满权重,评价结果的真实性需产品与合规确认。
